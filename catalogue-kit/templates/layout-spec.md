## 0. Inputs this spec relies on

- Approved entries and chapters (Checkpoint B, decision ids: …)
- Reference designs used, with the role of each (for example "Figma eTextbook file, library and detail frames: catalogue browsing pattern only")
- What is deliberately not reused from those references, and why

## 1. Contents and overview

Purpose, review date, source coverage summary (from the ledger, no invented percentages), status legend (text and icon, not color alone), chapter list in reading order. Search and filters are available here without replacing the reading order.

## 2. Chapter opener

The chapter's user goal in one or two sentences; its functions in order; links to related chapters (no duplicated entries).

## 3. Function reading page

Order on every screen size:

1. Title
2. Source-labelled visual + caption (`imageOrigin` visible)
3. Purpose and action → result explanation
4. Status, date, and limitations
5. Related functions
6. Expandable evidence and review history
7. Open questions

## 4. Stack review (one entry at a time)

Remaining count visible. Previous / next buttons and keyboard keys (say which). Gestures optional, never required. Status updates (if in scope) require a reason and evidence note and append history.

## 5. Carousel comparison

Browse related functions side by side. Keeps the selected entry and active filters when moving. Buttons plus arrow keys. Announces position ("3 of 8") to screen readers.

## 6. Review summary

Unresolved questions, entries changed since the last review, entries flagged for recheck. No invented completion counts.

## 7. Responsive behavior

Desktop layout notes. Mobile single-column order as in §3. Minimum touch target size. No drag-only workflows, no hover-only information, no color-only status.

## 8. Keyboard and single-pointer alternatives

A table: every interaction → keyboard path → single-pointer path.

## 9. Open layout questions for the owner

Each with a recommendation and its tradeoff.
