Updated interface principle

The database can be structured.

The experience should feel spatial.

So the property graph may contain:

Primitive → Operator → Skill → Artifact → Image → Lesson

But the interface should not show that as a rigid admin table.

Instead, it should let you call up different spaces depending on what you are doing.

⸻

The “callable spaces” model

The Replit project should be organized around modes of attention, not fixed pages.

1. The Canvas Space

Default view.

A nearly empty visual field.

You begin with one object:

circle

or one image, one artifact, one skill, one lesson seed.

From that center, you can expand outward.

Behavior

* Click a primitive → its dendrites appear.
* Click an image → related primitives glow.
* Click an operator → examples drift into view.
* Click a math concept → construction marks appear.
* Click a lesson → activities unfold.

The space breathes. It does not trap.

⸻

2. The Gallery Space

Called only when needed.

Purpose:

Show images first.

No big text blocks.

Images arrange themselves by:

* primitive
* operator
* culture
* artifact category
* execution skill
* math concept

Example call:

show circle + radiation + seals

The gallery appears as an image field.

Captions stay tiny until called.

⸻

3. The Graph Space

Not a permanent graph panel.

A summoned relationship view.

Purpose:

Show why things are connected.

Example:

circle → radiation → radial division → radius → sun disk images

The graph should appear only when the user asks to see relationships.

It can be dismissed back into the canvas.

⸻

4. The Compare Space

This is crucial for your curriculum.

Called when you want:

same primitive, different cultures

or

same skill, different artifacts

Example:

compare spiral in Newgrange, Maori koru, Ionic volute, galaxies

The result should be a sparse comparison field:

* four to eight images
* minimal labels
* hover/tap for details
* optional math overlay

⸻

5. The Construction Space

This is where art becomes skill.

Called when you want to turn an image into an exercise.

Example:

turn this image into a radial division lesson

The app shows:

* image
* ghost geometry overlay
* primitive breakdown
* execution steps
* math concept
* grade-band options

This is where the curriculum actually gets made.

⸻

6. The Source Space

Called only when needed.

Purpose:

Verify image location, source, rights, citation, confidence.

This should never dominate the main experience.

It appears like a quiet provenance drawer and disappears when done.

⸻

UI rule: image first, explanation on demand

Every object should have layers of disclosure.

Default

Image only.

First call

Primitive tags.

circle · line · star

Second call

Operator tags.

radiation · enclosure · repetition

Third call

Skill tags.

radial division · contour line · cross-hatching

Fourth call

Math tags.

radius · angle partition · circumference

Fifth call

Cultural/source notes.

This respects your visual curriculum: text is not the host. Text is the lantern.

How this changes the Replit app design

The app should not be built as:

Header
Sidebar
Main panel
Right panel
Footer

It should be built as:

Visual field
Summonable spaces
Floating commands
Contextual overlays
Dismissible detail layers
Saved constellations

Better language for the Replit prompt:

Build a minimalist, image-first curriculum database interface. Avoid static headers, dashboards, persistent sidebars, or heavy panels. The default experience should be an open visual canvas. Users summon spaces such as Gallery, Graph, Compare, Construction, Lesson, and Source through a command palette or object interaction. Text appears only as progressive disclosure over images and graph nodes.

⸻

Recommended interaction pattern

Primary gesture

Click or tap an object.

The object becomes the center.

Nearby possibilities appear:

primitive
operator
skill
math
artifact
lesson
source

Not as a sidebar.
As a small constellation around the object.

Secondary gesture

Command palette.

Examples:

show wave + textiles
compare circle as enclosure
build lesson from this image
trace math in this artifact
show sources
hide text

Third gesture

Semantic zoom.

Zoomed out:

* visual constellations
* clusters
* shapes
* image fields

Zoomed in:

* artifact cards
* source notes
* lesson details
* math construction

⸻

Data model should support spaces

Each “space” is not a separate database.
It is a different view of the same graph.

Example view object

{
  "id": "space_circle_radiation_gallery",
  "type": "GallerySpace",
  "query": {
    "primitive": "circle",
    "operator": "radiation",
    "artifact_categories": ["seal", "painting", "architecture", "diagram"]
  },
  "layout": "image_field",
  "text_density": "minimal",
  "overlays": ["primitive_tags", "operator_tags"],
  "default_sort": "culture_period"
}

Example construction space

{
  "id": "space_radial_division_construction",
  "type": "ConstructionSpace",
  "center_node": "skill:radial_division",
  "shows": [
    "image",
    "geometry_overlay",
    "execution_steps",
    "math_links",
    "grade_band_variants"
  ],
  "text_density": "progressive"
}

The graph stays stable.
The spaces are temporary lenses.

⸻

Good names for the callable spaces

You may want poetic but functional names:

Space	Function
Field	open starting canvas
Gallery	image evidence
Constellation	graph relationships
Mirror	cross-cultural comparison
Trace	construction and execution
Lesson Seed	curriculum generation
Provenance	source and rights
Atlas	saved collections

“Panel” language can be avoided entirely.

⸻

Minimalist layout principle

Keep visible at rest:

* one image, primitive, or graph node
* empty space
* subtle command affordance
* no permanent navigation furniture

Reveal only when called:

* metadata
* source
* math
* lesson
* related images
* relationship graph

The interface should feel like asking the database to exhale a specific room.

⸻

The Replit project should store this preference as a design doctrine

I would include a file like:

/design-principles.md

With this:

The app is not a dashboard.
The app is a minimalist visual research studio.
Images are primary.
Text is progressive disclosure.
Graph structure is callable, not permanently displayed.
No static headers, persistent sidebars, or heavy panels.
Users summon spaces: Field, Gallery, Constellation, Mirror, Trace, Lesson Seed, Provenance, Atlas.
Every space should be dismissible.
Every object can become the center.

That way the design does not drift into “spreadsheet wearing a museum costume.” 🪶
