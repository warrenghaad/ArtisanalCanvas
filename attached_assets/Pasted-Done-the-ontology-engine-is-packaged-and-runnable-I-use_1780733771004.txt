## What I built

Created a drop-in module at:

```text
project-euclid-geometry/
```

It includes the requested registry substrate, inference utilities, tests, CLI, seed nodes, and a small ingest automation layer so a shape/concept can trigger:

1. registry matching,
2. composition inference,
3. research query generation,
4. Day A / Day B separated design brief generation,
5. suggested output paths for research JSON, SVG/design, and GECD nodes.

The extra automation file is:

```text
/src/geometry/ingest.ts
```

That file powers:

```bash
node dist/scripts/geometry-cli.js ingest --term circle --civilization Mesopotamia
```

## Assumptions made

1. No existing Project EUCLID repo was present in the workspace, so I created a clean drop-in package with the requested paths.
2. The Petzinger 32 list was treated as provisional, exactly as your spec requested.
3. Historical claims in GECD seed nodes are marked as curriculum seeds with source placeholders, not final verified claims.
4. The ingest automation does not perform live web/library search by itself. It generates structured research queries and design briefs so your backend, search agent, or connector layer can execute the search.
5. Day A metaphor-register and Day B function-register are stored separately in all GECD seed nodes.
